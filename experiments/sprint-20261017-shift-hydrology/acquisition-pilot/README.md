# Acquisition-subset development comparison

This is an exploratory comparison run while the official USGS service required a 913-second retry wait. It uses seven gauges whose complete, checksum-verified development requests were already cached. The subset is determined by acquisition progress, not outcome or model performance. One additional completely downloaded gauge, 03338780, has no accepted instantaneous discharge and contributes no rows. No reserved geographic-test observations or final-year observations were opened for this pilot.

The candidates, features, calibration years, thresholds and model settings are identical to the frozen main experiment. The five development gauges train on 2021-2022, calibrate on 2023 and validate on 2024. Two geographic-validation gauges are evaluated in 2024. This is not a completed independent test, and its results cannot justify promotion or changes to the frozen experiment. The pilot contains 76,548 rows across three horizons. At each horizon, validation contains 24 eligible temporal events and 13 geographic events.

The linear six-hour rise projection has the highest equal-weight validation AP at every horizon: 0.2509, 0.2042 and 0.1879 at 6, 12 and 24 hours. The best learned AP at those horizons is 0.1891 for LightGBM dynamics, 0.1569 for XGBoost dynamics and 0.1531 for physical-residual LightGBM. Multiscale LightGBM dynamics outperform its delayed-flow ablation at every horizon, but that finding does not establish value beyond the physical baseline. Twenty-eight of thirty prespecified candidate/horizon combinations pass the positive calibration-slope requirement. The seasonal 6/12-hour candidates and no others fail that requirement. `summary.csv` contains the full development comparison.

Every candidate fit took less than 0.4 seconds. Peak process resident memory was below 350 MB. These small-data runtimes do not predict performance at national scale. The full frozen cohort remains the main experiment; the pilot did not change its candidates, thresholds, gates or reserved evaluation.

From the repository root, materialize the pilot once with `.venv/bin/python -m experiments.sprint-20261017-shift-hydrology.acquisition-pilot.run`. The script refuses existing output and makes no network request. In a separate Python process for each family, import `scripts.shift_hydrology_worker`, set its `OUT` to this directory using `pathlib.Path`, and call `fit` with `baseline`, `logistic`, `lightgbm` or `xgboost`. Set `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` and `VECLIB_MAXIMUM_THREADS` to 2. Keep boosting libraries in separate processes. Family selection JSON files preserve input/code hashes, settings, validation metrics, library versions and artifact hashes.
