# Demonstration and verification

## Preparation

Follow README setup, start the single-worker server, open port 8000, and wait for the portfolio refresh to finish. Set Supervisor access with your private `.env` token. Keep Jev disabled unless API costs have been authorized separately; the default demonstration sends no third-party inference requests. Provider results are time-dependent. Missing data are an uncertainty demonstration, never a reason to fabricate a value.

## Five-minute walkthrough

1. **Portfolio.** Show 60 EIA-attributed facilities and the ranked map. Explain the historical December 2024 inventory, timestamps and partial input coverage. A low partial score or absent report does not establish safety. Fixed index weights are heuristic environmental severity, not calibrated injury probabilities.
2. **Model evidence.** Open Model intelligence. Show 21,336 complete county-days across 24 counties, eight candidates per hazard, separate calibration and temporal/geographic selection, and final January–June 2026 tests. Distinguish the expanded benchmark from the identical ten-county comparison. Flood retained its original estimator; storm's validation winner did not improve matched final-test ranking and missed all three independent geographic events. Lower false alerts cost recall. Open reliability, threshold, county and uncertainty details rather than presenting precision alone.
3. **Supported and unsupported sites.** Select Palo Verde (6008) for the flood estimate, or Braidwood Generation Station (6022)/Catawba (6036) for storm, subject to forecast availability. Inspect the UTC target window, county representative point, calibrated probability, SHAP baseline and signed contributions. Only one hazard is supported at each of these facilities, so the combined ML index component stays unknown. Select W A Parish (3470) to show explicit out-of-population withholding. Weather, NWS and FEMA remain independent inputs; neither site-specific weather nor a warning validates the county classifier.
4. **Crew intelligence.** Submit a nonsensitive observation starting “HYPOTHETICAL DEMO ONLY — no field hazard observed.” Select wildlife and additional unstable terrain; leave text-sharing consent unchecked. Show the persisted labels, manual source, missing-consent explanation and pending status. Correct classifications; pending review remains unchanged. Reject the demonstration report afterward so it cannot become an active verified hazard. Optional photos remain local and are re-encoded without metadata. With configured, authorized Jev, consent permits only text transmission; explain uncertainty and human review rather than claiming fixture-based semantic accuracy.
5. **Independent safety workflows.** Show the clearly labeled lightning replay and timer reset. Live records remain separate; the internal 10-mile/30-minute rule and expiry require supervisor review, never automatic clearance. Open briefing history and generate tomorrow's facility-local briefing twice to demonstrate its immutable saved snapshot. ML tomorrow UTC is a different target from a local workday. Delivery remains unconfigured.

For the optional live Jev demonstration, first authorize the small provider cost and confirm the local server configuration. Submit only a clearly fictional, nonsensitive observation with text consent checked. Show independent hazard labels, Choice inbox, the defined Score urgency and clarification flag. A routine inbox never dismisses a report. Correct only manual categories, reload, and show that AI judgments and pending status remain intact. Filter a hazard suggested only by Jev and the pending clarification queue; show an empty combination so hidden reports cannot look absent. Reject the demonstration afterward. This is workflow verification, not an additional independent accuracy case.

## Limits and rerunning checks

No authentic independently labeled field evaluation, image inference, commercial lightning feed, external delivery, physical-device geolocation, public deployment, prospective model validation or safety certification was performed. The six earlier Jev fixture examples use hypothetical observations and hand-authored probabilities; they validate interpretation only. The ten later synthetic scenarios use real inference but author-supplied labels, tiny class counts and no field calibration. Retrospective storm diagnostics do not establish a predictive gain, and serving coverage remains restricted.

Run `.venv/bin/python -m pytest -q` and `npm --prefix frontend run build`. Reproduce the original benchmark with `.venv/bin/python -m scripts.reproduce_baseline`, storm diagnostics with `.venv/bin/python -m scripts.diagnose_storm`, and the no-network Jev plan with `.venv/bin/python -m scripts.evaluate_jev`. Its separate `--live` operation incurs provider calls and refuses to overwrite existing evidence. Expanded ingestion/training instructions are in README; `docs/EVALUATION.md` and `models/evaluation.json` contain the measured results. Read MODEL_CARD.md for timing, scope and uncertainty, RESEARCH.md for primary sources, and OPERATIONS.md for provider configuration, consent, persistence and explicit recovery.
